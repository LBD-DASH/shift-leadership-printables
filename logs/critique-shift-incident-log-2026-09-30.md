# Printability critique — Shift Incident / Issue Log layout (2026-09-30)

Reviewing the Page 1 / Page 2 layout brief in `logs/2026-09-30.md` for print usability and what a real shift supervisor needs. Five specific fixes before this goes into Canva.

1. **The header strip crams six fields into one navy bar.** Site/Area, Date, Time found, Shift (4 tick boxes plus a blank), Reported by and Role are all specified as one line. Usable width on A4 inside 12mm margins is roughly 186mm (the same arithmetic the Weekly Check-in critique used on 2026-09-29) — six labelled fields, one of which is itself four tick boxes plus a write-in, will not fit legibly on a single line inside a navy bar with cream text. Split the strip into two rows (for example Site/Area / Date / Time found on row one, Shift + Reported by + Role on row two) before this goes into Canva.

2. **No row-height budget was written against the page.** Roughly totalling the brief's own numbers — header strip (~15mm), Box A (~15mm), Box B at 4 lines ≥8mm (~40mm), Box C at 3 lines (~30mm), Box D's table (~20mm), Box E at 2 lines (~20mm), Box F (~20mm), Box G's header row plus 5 rows ≥8mm (~50mm), and the footer (~20mm) — comes to roughly 230mm before adding gaps between the seven labelled boxes, section-label spacing and box borders. Against A4's usable height of about 273mm inside 12mm margins, that leaves under 45mm for seven section gaps plus all box padding and rules — dangerously tight. Do the same per-box mm arithmetic the 1:1 critique (2026-09-28) and Weekly Check-in critique (2026-09-29) both called for, on paper, before exporting, or Page 1 will come out oversized and need a rebuild.

3. **Box A's "wrap if needed" leaves the tick-box row unresolved for print.** A print-ready PDF has a fixed layout — it can't wrap dynamically the way a live form field can. Five options (Safety/near miss, Equipment, Quality/customer, Staffing/people, Other: ____) will not sit legibly on one row at 186mm usable width once each has a tick box, label and gap, especially with "Other" needing its own write-in space. Decide the exact row break now (for example three ticks on row one, two plus the Other write-in on row two) rather than leaving it to whoever builds the Canva file.

4. **Box D's equipment-status symbols have no on-page legend.** The brief uses ●OK / ◐Watch / ○Down inside the Impact table with no key explaining what each symbol means. Unlike Box A's tick-box options, which are self-explanatory from their labels, a filled, half-filled and empty circle is not an obvious code to a supervisor filling the sheet under pressure, or to whoever reads it at the next handover. Add a one-line legend under the table header, the same fix the Weekly Check-in critique required for its unexplained Energy scale on 2026-09-29.

5. **Box D's Impact table only has one row.** An incident that affects more than one piece of equipment, or has both a quality hit and a staffing impact, can't be recorded as separate lines — the layout forces everything into a single row's four cells, which pushes multi-part incidents toward cramped or overwritten cells. Give Box D 2–3 rows (matching the multi-row treatment already given to Box G's Actions table), or add an explicit instruction that a second Impact row continues onto the write-in lines in Box B if more than one asset or impact type is involved.
